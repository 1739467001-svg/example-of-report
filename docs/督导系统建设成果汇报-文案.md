## 一、项目背景与建设目标

### 1.1 为什么要建这个系统

研究生教育质量是研究生院的核心关切，**课堂教学督导**是教学质量保障体系中最直接、最有效的抓手之一。长期以来，研究生教学督导工作面临几个现实痛点：

- **找课难**：全校研究生课程分布在多个学院、两个校区，且存在单双周排课，督导专家很难快速定位"本周哪天、哪个学院、哪位老师"有课可听。
- **评价散**：听课评价主要依赖纸质评价表，填写、收集、归档环节多，结果难以沉淀。
- **统计弱**：评价数据散落在纸面，学院和研究生院缺乏"谁评了、评了多少、评得怎么样"的全局视图。
- **反馈慢**：评价结果向学院、向研究生院的传递链路长，难以及时形成质量改进闭环。

### 1.2 建设目标

围绕上述痛点，本项目的目标是打造一个 **数据驱动、流程闭环、多角色协同** 的研究生教学督导一体化平台，实现：

- 把"全校总课表"变成 **可检索、可督导、可评价、可统计** 的在线平台；
- 用 **标准化评价表** 取代纸质表格，让评价"填得方便、看得清楚、留得下来"；
- 用 **数据看板** 让学院和研究生院随时掌握督导进度与质量分布；
- 用 **消息通知** 打通"评价完成 → 学院/研究生院知晓"的反馈链路。

## 二、系统概览

### 2.1 一句话定位

> **一个基于全校真实课表数据、覆盖督导全流程的研究生教学督导一体化平台。**

系统完全以学校真实数据为底座搭建——课程、教师、学院、校区、排课规则全部来源于《全校总课表》，用户与角色来源于《督导系统角色信息表》，评价表单严格按照学校现行的《课程评价表》构建，做到"所见即真实业务"。

### 2.2 数据底座（真实数据驱动）

系统深度解析了全校总课表，自动建立了完整的业务数据库：

| 数据维度 | 规模 | 说明 |
| --- | --- | --- |
| 研究生课程 | **1,344 门** | 全校研究生院全部课程记录 |
| 学院 | **22 个** | 覆盖全校开课学院 |
| 校区 | **2 个** | 含下沙等校区 |
| 授课教师 | **595 名** | 全部主讲教师 |
| 系统用户 | **58 位** | 按真实角色名单导入 |
| 排课规则 | 单双周 | 完整还原单双周排课差异 |

> 系统不是"演示用的样例数据"，而是直接面向真实业务可用。

### 2.3 设计风格与多端适配

- **商务蓝**主色调，简洁、专业、贴合学校气质；
- 采用现代化卡片式仪表盘布局，信息层次清晰；
- **响应式设计**，电脑端、平板端、手机端均可正常使用。

## 三、四类角色与权限体系

系统设计了贴合研究生院真实管理结构的四类角色，权限层层递进、职责清晰：

| 角色 | 权限范围 | 核心职责 |
| --- | --- | --- |
| **督导专家** | 全校课程 | 检索课程、加入听课计划、填写课程评价、查看本人评价记录 |
| **督导组长** | 全校课程 | 在督导专家全部功能基础上，可查看**所有**督导专家的评价记录 |
| **学院教学秘书** | 本学院 | 查看本学院被督导课程及评价详情（**只读**，不可修改删除）；掌握本院督导进度 |
| **研究生院主管** | 全研究生院 | 最高权限（超级管理员）：全局统计看板、用户管理、各学院督导数据总览 |

权限设计要点：

- **数据隔离**：学院教学秘书仅能看到本学院数据（例如工商管理学院秘书仅见本院课程与评价）；
- **只读保护**：学院秘书对评价只读，保证评价数据的客观与不可篡改；
- **逐级汇总**：从督导专家个人 → 督导组长全员 → 学院本院 → 研究生院全局，数据逐级汇聚。

## 四、核心功能模块

### 4.1 全校课程与多维筛选

- 全校 1,344 门课程在线检索；
- 支持按 **周次、星期、学院、校区、教师** 等多维度组合筛选；
- 筛选逻辑与原始课表完全一致（如"会计学院 + 第 3 周"精确联动），督导专家可快速锁定目标课程。

### 4.2 听课计划管理（待办 + 日历视图）

- 督导专家/组长可将有意向的课程一键 **加入听课计划**（类似待办清单）；
- 提供 **日历视图**：以"节次 × 星期"网格直观展示当周听课安排，支持按周切换；
- 待听课 / 已评价 / 已取消 三种状态以不同颜色清晰区分；
- 课前自动 **站内提醒**，避免漏听。

### 4.3 标准化课程评价表

- 评价表单 **严格按照学校现行《课程评价表》** 构建；
- 包含 **20 项定量评分**（如教学内容、学生状态、课程内容、教学过程等多个维度）+ **定性文字评价**（课程亮点、具体建议等）；
- 支持 **保存草稿**，可分多次完成；评价项含互斥单选（如"科研转化融合度 / 前沿视野传递"二选一）等贴合实际的设计；
- 系统自动计算综合评分（如总体 4.9 / 5.0），并以星级直观呈现。

### 4.4 评价记录与权限分级查看

- 已评价课程形成记录列表，支持 **查看、修改**；
- 权限分级：督导专家看本人、督导组长看全员、学院秘书看本院（只读）、研究生院主管看全局；
- 评价详情页提供"各维度评分概览"，一眼看清各项得分。

### 4.5 数据仪表盘与统计分析

- **研究生院主管仪表盘**：全校课程总数、已完成督导评价数、督导专家人数、覆盖学院数等关键指标一屏总览；
- 图形化展示各学院评价次数、评分分布、督导活跃度；
- **学院/研究生院评价进度看板**：清晰展示"已评价 / 全部课程"的进度，并可下钻查看具体哪些课程已评、哪些未评。

### 4.6 消息通知与提醒

- 督导评价提交后，系统 **自动通知** 研究生院主管与对应学院教学秘书；
- 听课计划课前自动推送站内提醒；
- 打通"评价完成 → 学院/研究生院知晓"的反馈链路。

### 4.7 工号登录与用户管理

- 全体用户以 **工号** 作为唯一登录凭证，初始密码即工号，支持首次登录后自助修改密码；
- 研究生院主管可进行用户与角色管理。

## 五、督导业务闭环（核心价值）

系统最大的价值在于把分散的督导环节串成了一条 **完整闭环**：

```
全校课表  →  多维筛选  →  加入听课计划  →  课堂听课  →  在线评价（标准化表单）
                                                              │
                                                              ▼
持续改进  ←  数据统计分析  ←  学院/研究生院查看  ←  评价提交后自动通知
```

> 从"一张张纸质评价表"到"一条可沉淀、可统计、可追溯的数字化督导链路"，这是本系统对研究生教学质量保障工作最实质的提升。

## 七、开发方式（简要说明）

本系统采用 **AI 辅助 + 数据驱动的敏捷开发模式**：

- 直接以学校真实 Excel 课表为输入，**自动解析建库**，省去大量人工录入与结构设计；
- 围绕督导专家、研究生院的 **真实使用反馈快速迭代**，经多轮打磨持续修复与优化；
- 显著压缩了从需求到可用系统的周期。

> 该方式让"真实数据 → 可用系统"的转化更快、更贴合一线实际需求。

## 附录二：答辩 Q&A 预演

**一、建设与数据**

1. **数据来源是否可靠？如何保证与真实课表一致？**
   全部数据来源于学校《全校总课表》等真实文件，自动解析建库（1,344 门课、22 学院、595 名教师），筛选逻辑与原课表一致，可随新学期课表定期更新。

2. **评价数据安全吗？会不会被篡改？**
   工号唯一登录 + 角色权限控制；学院教学秘书对评价为只读、不可修改删除；数据存于 PostgreSQL 关系型数据库，操作可追溯。

3. **评价标准如何统一？**
   评价表完全复刻学校现行《课程评价表》，20 项定量 + 定性，系统自动计算综合评分，确保口径一致、结果可比。

4. **能否与现有信息化系统对接？**
   系统前后端分离、以工号为唯一标识，预留数据导入与接口能力，可逐步与研究生管理等系统对接。

**二、应用与推广**

5. **老师上手难不难？**
   工号即账号、初始密码为工号；多维筛选快速找课，日历视图 + 课前提醒，评价支持保存草稿分次完成，上手成本低。

6. **研究生院如何掌握全校督导情况？**
   主管数据看板一屏总览（课程数、已完成评价、督导专家数、覆盖学院），并按学院图形化展示评价次数与评分分布。

7. **能否支持 MBA 等其他课程？**
   可扩展。后续计划导入 MBA 等专业学位课程及对应评价表。

8. **下一步规划是什么？**
   分管院长角色、PDF/Excel 报表导出、语音评价自动打分、教师评价趋势与同学院对标分析。
